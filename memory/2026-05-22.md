# 2026-05-22

- Diagnosed the `rebuild-depth-chart` GitHub Actions failure at `Commit refreshed depth chart artifacts` as a workflow ordering problem, not a depth chart generator bug.
- The job was committing `public/data/depth-chart.json` and `public/sitemap.xml`, then running `git pull --rebase origin main` afterward.
- That pattern is brittle because `public/sitemap.xml` is a shared generated artifact that other automation can update between checkout and push, creating a post-commit rebase conflict inside the same step.
- Fixed `.github/workflows/depth-chart-update.yml` by rebasing onto `origin/main` immediately after checkout, before any artifact generation, and by removing the post-commit `git pull --rebase` / extra `git add -A`.
- Kept the workflow behavior otherwise the same: rebuild depth chart data, regenerate sitemap, commit only the intended artifacts, and push to `main`.
- Fixed the schedule page in `public/schedule.html` to use the shared `<header>` / `<footer>` mount points and the shared `site-footer.js` renderer, replacing the nonstandard placeholder div roots that prevented the page from matching the rest of the site layout.
- Removed the desktop fixed-height inner scroll behavior from both schedule tables so all rows render inline on desktop, while preserving a mobile-only capped scroll fallback for the tabbed single-column view.
- Reworked the schedule hero summaries to derive played/upcoming opponent metrics directly from `public/data/game-log.json` row data instead of the pre-rounded `summary.sosPlayed` / `summary.sosUpcoming` snapshot, which had collapsed different opponent batting averages into the same displayed `.240`.
- Added collective opponent record and collective winning percentage to both the `Opponents Faced` and `Opponents Remaining` sections using the same played/upcoming row datasets as the other displayed schedule metrics.
